# 需求锚点只固定要做的事

`gitlab-matt-workflow` 用目标项目上的一条 GitLab Issue 固定这次要做什么，go 之后再交给 `matt-dev-workflow` 实现。Issue 正文只保留已经说清的背景、要做什么、验收；这次若写正文，就删掉其余内容，包括「未提供。」和进展。go 之后不再改这条 Issue。spec 可以更细，但不得与锚点矛盾；一旦矛盾，自动阶段停下，不写矛盾的 spec，不改 Issue，也不提交。

不把 spec、提交或结论写回 Issue，不用「未提供。」给缺的节占位，也不在矛盾时缩范围继续做。缺的节整节不出现。不提交代码仍沿用「Issue 技能不创建提交」。`gitlab-issues` 单独写正文时，同样只保留已经说清的节。
