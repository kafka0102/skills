# GitLab Issue

使用本机已登录的 `glab` 修改目标项目中的 GitLab Issue。参数以当前 `glab issue <command> --help` 为准。不保存 token，不打印凭据。脚本或命令输出里若有 token，不转述。

只读写 origin 解析出的这一个项目。不实现需求，不创建 commit，不关闭，不删除，也不把其他仓库的 Issue 链到这一条。

## 确定目标项目

运行本技能目录下的解析脚本，参数为当前工作目录：

```bash
node <skill-dir>/scripts/resolve-project.mjs "$PWD"
```

脚本成功时输出 `host`、`projectPath`、`repo`。后续命令使用 `GITLAB_HOST=<host>`，`-R` 使用 `repo`。

完成标准：`glab auth status --hostname <host>` 成功。脚本或登录失败时停止，并报告脚本错误；不改用目录名、其他 remote，也不写死项目路径。origin 不是 GitLab 时脚本会停止，本技能也停止。

## 判断动作

- 用户给出本仓库的 Issue 编号或 URL：只操作这一条。不搜索，不新建。
- 消息含有「远程 Issue 已创建，更新这一条，不要新建。」并且给出一条 Issue URL：这就是给出了这一条，并且要求更新描述。不是分析草稿，也不是新建。URL 可以在下一行，也可以在同一条消息里。这句话本身不写入正文。
- URL 的项目和 origin 解析出的项目不一致：停止，并说明两边的 host 与项目路径。不新建，不改 URL 那一侧，也不改 origin 这一侧。
- 编号和 URL 指向不同 Issue：停止。
- 没有编号、没有 URL、也没有上面这句更新句子时：明确说新建才创建，搜索到的相近 Issue 只在结果里提一句。要求创建但没说新建，就先搜索，同一事项已有开放 Issue 则更新那一条；没有开放的同一事项就停止，不新建。要求修改或评论但定位不到，就停止，不新建。
- 只说分析或草稿，又没有上面的更新句子：整理后放在回复里，不写入。
- 用户说完成某条 Issue：只整理并写入正文或评论。不提交代码，不关闭。

Issue URL 的项目是 `/-/issues/<编号>` 之前的路径。host 与脚本的 `host` 比，路径与 `projectPath` 比。host 忽略大小写。

完成标准：调用写入命令前只有一个动作。需要编号的动作已经确定到一条属于目标项目的 Issue。

## 整理说法

创建或修改描述时，正文只有这些节，只写已经说清的节。中文标题用：

```markdown
## 背景

## 要做什么

## 验收
```

用户用其他语言时，这三节仍是背景、要做的事、验收，标题随该语言。

第一次把口述或简短任务整理进正文时，「背景」里放用户原话，原样引用，并标明这是原始说法：

```markdown
## 背景

原始说法：

> 用户的原话
```

之后的更新先读现有正文，再整篇替换成当前已经说清的节。仍然有效的旧节保留。被否定的内容不留。没有说清的节不出现。这是重写当前事实，不是另附一份差异。

进展、结论、当前状态、验证结果和 commit 不进入正文。当前还没有任何说清的节时，不创建，也不改描述。

评论只理顺要说的话，不套这三节，也不改标题或正文。

正文和评论只写给人读的句子。不写会在 GitLab 上执行的 quick action。

完成标准：写入的正文只含已经说清的那些节。标题是一句问题或期望能力，只在创建时写入。用户这次没有明确要求改标题时，更新不动标题。

## 搜索同一事项

只在判断动作要求搜索或定位时搜索。

```bash
GITLAB_HOST=<host> glab issue list -R <repo> --search "<关键词>" -O json
```

读候选的标题和描述再判断。列表不含描述时，对候选再 view。标题相近但事项不同的不合并。只把开放 Issue 当作可更新的同一事项。

完成标准：每个被当作同一事项的候选都读过描述。

## 写入

更新前先读这一条：

```bash
GITLAB_HOST=<host> glab issue view <id> -R <repo> -F json
```

描述用 `mktemp` 写成临时文件，再整篇替换。不把该文件留在仓库里。

更新描述：

```bash
GITLAB_HOST=<host> glab issue update <id> -R <repo> --description-file <临时文件>
```

创建：

```bash
GITLAB_HOST=<host> glab issue create -R <repo> -t "<标题>" --description-file <临时文件> -y
```

命令里的 Issue 用编号，仓库用 `-R` 的 `repo`。

元数据只传用户这次点名的标签、负责人、里程碑、截止日期，并且该参数要在当前命令的 `--help` 里。没点名的不传。点了名但没写上的，在回复里说明。

不关闭、不删除 Issue 或评论。用户要求关闭或删除时停止，不调用对应命令。

用户这次没有要求改正文时，不写描述文件。用户这次没有明确要求改标题时，不传标题。

评论：

```bash
GITLAB_HOST=<host> glab issue note <id> -R <repo> -m "<整理后的评论>"
```

写入后再 view 一次。

完成标准：回读的标题、描述，以及本次点名且已写上的字段，与刚写入的一致。回复完整 Issue URL、动作是创建、更新还是评论，以及点了名但没写上的字段。
